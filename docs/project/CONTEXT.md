# Project context

Read down this index until you have the context needed for your task.

| Work | Read | Produce |
| --- | --- | --- |
| Understand or refine the project | [Brief](brief.md) | Proposed decisions, assumptions, and scope updates |
| Decide technical direction | Brief and [architecture](architecture.md) | Evidence-backed architecture decisions |
| Plan or implement a task | Brief, [task guidance](tasks/README.md), and the selected task's prerequisites | Focused changes and verification evidence |
| Review a change | Selected task contract and relevant source diff | Acceptance results and handoff |

The brief owns project goals and decisions. Architecture owns technical decisions. Task files own individual deliverables. Reference these sources instead of duplicating their rules. Update affected task context after an upstream decision changes.
